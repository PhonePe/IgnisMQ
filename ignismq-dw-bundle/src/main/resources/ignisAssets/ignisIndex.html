Connecting

How your role is decided. IgnisMQ ships no authentication of its own; the application it is embedded in populates the Jersey SecurityContext, and the console's actions are closed unless it grants ignismq_operate (or ignismq_deactivate).

If your application authenticates with cookies, leave this empty — the browser already sends them. If it expects a token, paste the full value the Authorization header should carry — including whatever prefix your application expects, such as Bearer <token> or O-Bearer <token> — and every request will carry it verbatim. A value the application does not recognise leaves you unauthenticated, which shows up as every action staying disabled.

Held in sessionStorage, so it is gone when this tab closes. It is readable by any script on this origin, so use a short-lived token and serve the console over HTTPS.

Actions

Add consumers this instance Starts more consumer tasks here. Other instances are unchanged.
Stop consumers this instance Stops consumer tasks here. Messages are not lost; the remaining consumers take them.
Drain the sideline now this instance One-shot shovel of sidelined messages back into the main queue. Nothing is stored.
Schedule a repeating shovel cluster Stored on the queue. Every instance adopts it on its next refresh.
Sweep now cluster Re-homes messages a consumer claimed and never finished. Runs synchronously and can take a while on a large queue.
Deactivate cluster Irreversible. No API activates a queue again. Consumers stop everywhere and messages still in the queue are left where they are. Needs the separate ignismq_deactivate role; type the queue name to confirm.

These are one process's numbers, read live from its meter registry. IgnisMQ has no broker and no register of instances, so there is no cluster total here and there cannot be one — scrape ignismq.* and magazine.* and aggregate in your metrics backend.

Hover the beside any meter for what it measures.

Timers are in milliseconds. Their mean covers the whole life of this process and never decays, while their max is a rolling two-minute window — so after a spike settles the max can sit below the mean, which is the two windows disagreeing rather than a fault.

Counters are totals since this process started, never rates.

Gauges are the value right now.

Bars are scaled against the largest row in their own table, so they compare within a table and not across them.
